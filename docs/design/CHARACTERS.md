# Characters: the Locker, the code, and hand-made parts

How Climbers are built, how players dress them, and how to add new parts. Art style: [ART_DIRECTION.md](./ART_DIRECTION.md).

> **Status: first pass, to revisit.** The Locker, its slots, the stances and paint are a starting point, not fixed rules for the game. Expect the options, proportions and workflow below to change once the character design gets its proper pass.

## What players can change (the Locker)

The Locker is the screen before you enter the Base, reopened with **Edit character**. A rotating 3D stage sits on the left and the toolbox on the right. Each tab moves the camera to the body region it edits.

| Tab | Slots |
|---|---|
| Body | Skin colour · **Build** (slim, regular, broad) · **Stance** (relaxed, hands in pockets, fighter, hands on hips) |
| Hair | Style (none, spiky, bun, mohawk, messy, long, buzz cut, flame) · colour, shared with hats |
| Face & hats | Headwear (none, cap, beanie, headband, crown) · eyes (plain, visor band, goggles, shades) |
| Top | T-shirt, long sleeves, hoodie, open jacket, tank top, no top · colour |
| Bottoms | Trousers, shorts, baggy, skirt · colour |
| Shoes | Sneakers, boots, sandals · colour |
| Paint | Brush, eraser and mirror on 16 colours, with undo/redo and Clear all. Paints markings, tattoos, face paint and logos onto the voxels the Climber already has. |

Every colour slot has swatches plus a custom colour picker; the server accepts any `#rrggbb`. Paint holds up to 512 voxels.

## Where the code lives

| To change | File |
|---|---|
| The **options** a slot offers, and their defaults | `packages/shared/src/identity.ts` (`HAIR`, `TOP`, `BUILD`…, `DEFAULT_LOOK`, `parseLook`). The server validates against these, so a new option starts here. |
| **What a part looks like** (head size, torso, sleeves, shoes, hair shapes) | `apps/client/src/avatar/avatarVoxels.ts`, in `buildAvatar()`. Parts are filled with `grid.box(x0, y0, z0, x1, y1, z1, colour)` in voxels (1 voxel = 0.1 m). |
| **Proportions per build** (torso width, arm and leg thickness, where limbs attach) | `BUILDS` and `rigFor()` in the same file |
| **Animation**: walk swing, jump pose, breathing, the four stances | `apps/client/src/avatar/VoxelAvatar.tsx` (`IDLE_POSES`, `useFrame`) |
| Option **names** shown in the Locker | `apps/client/src/identity/editorOptions.ts` (`LABELS`) |
| The **Locker** screen and its camera | `apps/client/src/identity/CharacterEditor.tsx`, `EditorStage.tsx` |
| **Hand-made parts** | `apps/client/src/avatar/parts/*.vox` (see below) |

**The voxel grid of a Climber**, in each part's own coordinates. The Climber faces +z, x runs to their left (−x) and right (+x), and y is up.

```
head   pivot at the neck (y 13 in body space)   voxels x −2..2, y 0..4, z −2..2; face at z = 2
torso  no pivot (body space)                    x −w..w (w = 2, 3 or 4 by build), y 6..12, z −1..1
arms   pivot at the shoulder                    y −7..−1 (hand at −7), 2 or 3 voxels thick
legs   pivot at the hip (y 7 in body space)     y −7..−2 (foot at −7, toes poke to z = 2)
```

### Adding a code-built option, e.g. a new hat

1. Add its id to `HEADWEAR` in `packages/shared/src/identity.ts`.
2. Draw it in `headwear()` in `avatarVoxels.ts`. Work in head coordinates: the scalp's top layer is y = 5.
3. Give it a label in `editorOptions.ts`.
4. Run `npm test` (shared and server) and `npm run lint`, then look at it in the Locker.

## Hand-made parts with MagicaVoxel

Use this for parts worth sculpting by hand: hairstyles, hats and, later, bosses. Today the hair slot loads `.vox` files. Other slots follow the same pattern when needed.

1. **Start from the template.** Open `art/templates/head.vox` in [MagicaVoxel](https://ephtracy.github.io/). The grey block is the Climber's head (5×5×5). Regenerate the templates any time with `npm run vox:templates -w apps/client`.
2. **Sculpt around the head.** Keep the canvas size (11 × 11 wide, 14 tall). The face looks toward MagicaVoxel's front view (−y).
3. **Colours:**
   - **Greys follow the player's chosen colour.** `#c0c0c0` becomes exactly their hair colour; lighter greys are highlights and darker greys are shadows.
   - **Any other colour stays as you painted it**, for example a gold clip or a red gem.
   - The grey reference head uses palette slot 255, which the game ignores, so you don't need to delete it.
4. **Save** as `apps/client/src/avatar/parts/hair-<name>.vox`. For example, `hair-flame.vox` is the "flame" hairstyle; the sample in the repo is generated by the templates script, so open and edit it freely.
5. **Register the name** in `HAIR` (shared/identity.ts) and give it a label. A `.vox` part with the same name as a code-built style replaces it.
6. Reload the Locker. A broken file logs a warning and falls back to the code-built style; it never breaks the game.

Keep parts readable: big shapes, 2–3 shades per colour, no single-voxel noise. Parts are meshed by the same code as everything else (AO, merged faces), so they match the world.

## Ready-made characters from other people?

Free voxel and low-poly characters exist, for example on Sketchfab (filter by CC0 or CC-BY), itch.io asset packs, Kenney and Quaternius. They are useful as **reference or as NPCs**. They aren't a drop-in replacement for Climbers today: the current Locker dresses Climbers built from swappable parts on the grid above. Check every licence for commercial use and credit CC-BY authors in `art/CREDITS.md`. Never use characters from other games or anime, even as "inspiration copies".

## Blender

Blender stays useful for non-voxel props. Character parts should be voxel and on the grid, so MagicaVoxel is the right tool for them. If you do model a part in Blender, voxelise it (for example with MagicaVoxel's import, or the Voxel Remesh modifier and a `.vox` export add-on) before it goes into `parts/`.
